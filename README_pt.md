## sobre mim

sou estudante de Engenharia de Software na **PUC Minas**, construindo minha carreira na interseção entre **Arquitetura de Software**, **System Design**, **Engenharia de Produto** e **IA** — quero aprender a **projetar sistemas com intenção**: entender o problema, avaliar decisões arquiteturais e construir soluções alinhadas ao que o produto realmente precisa. Ainda estou longe de ser arquiteta — mas esse é exatamente o destino que me move.

desenvolvo sistemas full-stack com foco em back-end — Node.js, Java e TypeScript — enquanto aprofundo os fundamentos de arquitetura e estudo como a IA está mudando a forma de construir software, do **Specification-Driven Development (SDD)** aos **agentes de IA** e à **engenharia aumentada por IA**. Meu trabalho é guiado por alguns princípios: **escrever código que escala, documentar o que importa e nunca parar de aprender.**

o que mais me atrai:

- 📐 **SDD e arquitetura** — rastreabilidade entre requisitos, implementação e validação
- 🧭 **gestão de projetos e de processos** — como times planejam, decidem e entregam
- 🤝 **pessoas e liderança técnica** — colaborar, ensinar e adaptar a linguagem técnica a cada público

## projetos em destaque

### 🌿 [EcoShop](https://github.com/maria-brito15/ecoshop-nextjs) — Plataforma de E-commerce Sustentável `🏆 Finalista PUC Minas`

Plataforma full-stack de e-commerce/catálogo de produtos sustentáveis com um **scanner de materiais com IA**. Nasceu como projeto acadêmico finalista e foi totalmente reescrita por mim, sozinha, para consolidar o aprendizado com uma stack moderna.

**v1 · Original (2025) — Java + Spark Framework**
> Versão acadêmica selecionada entre os melhores trabalhos do semestre. Arquitetura MVC clássica com camadas Controller → Service → DAO, PostgreSQL direto via JDBC, sanitização manual de entradas contra XSS, autenticação por sessão com BCrypt, testes com JUnit 5 + Mockito e deploy com Docker no Render.

`Java` `Spark Framework` `PostgreSQL` `JDBC` `BCrypt` `JUnit 5` `Mockito` `Docker`

**v2 · Refatoração (2026) — Next.js 15 + TypeScript**
> Reescrita completa e solo com uma stack moderna. App Router, cache em duas camadas (Redis + Map com stale-while-revalidate), Prisma ORM tipado, JWT stateless com middleware centralizado e validação com Zod em todas as rotas.

- **IA com responsabilidades distintas:** um modelo que treinei no Azure Custom Vision identifica materiais recicláveis a partir de imagens; o Gemini 2.0 Flash gera análises de sustentabilidade — cada integração resolve uma parte diferente do problema de produto
- **Resiliência:** degradação graciosa se qualquer um dos serviços de IA ficar indisponível
- Cache em duas camadas: **Redis** (servidor) + `Map` com stale-while-revalidate (cliente)
- Controle de acesso por perfil: `ADMIN`, `CLIENTE`, `MARCA`
- CI/CD com GitHub Actions + GitHub Container Registry (lint, type-check, build, deploy via SSH)

`Next.js 15` `TypeScript 5` `Prisma 7` `PostgreSQL` `Redis 4` `JWT / jose` `Zod 3` `React 19` `Tailwind CSS 4` `Azure Custom Vision` `Gemini 2.0 Flash` `Docker` `GitHub Actions`

**v3 · Refatoração com SDD (2026 – em andamento)**
> Refatorando o projeto com **Specification-Driven Development**: as especificações guiam o planejamento, a implementação e a validação de cada mudança, e também organizam a manutenção das duas integrações de IA.

### ♻️ [Reciclaki](https://github.com/maria-brito15/plf-es-2026-2-ti2-7587100-reciclaki) — Plataforma de Coleta Seletiva e Reciclagem `👥 Equipe de 7`

Evolução de um sistema de apoio à coleta seletiva em Belo Horizonte: cidadãos descobrem onde descartar cada material e ganham pontos trocáveis por recompensas. Desenvolvido no Trabalho Interdisciplinar (Engenharia de Software, PUC Minas), de outubro a novembro de 2026.

- Escopo redefinido a partir de entrevistas qualitativas: o modelo de dados caiu de **17 para 11 coleções**, com três perfis (cidadão, catador e gestor) — decisões registradas em uma **especificação única usada como fonte de verdade**
- Mapa de pontos de coleta com consulta geoespacial (índice `2dsphere`), react-leaflet e OpenStreetMap
- Cálculo de pontos, resgate de recompensas, recolhimento por cooperativas e módulo de denúncias da comunidade
- JWT em cookie httpOnly (jose), controle de acesso por perfil via middleware e validação com Zod
- **Mais de 400 testes automatizados** com Vitest e Testing Library (serviços, rotas, regras de pontuação e componentes)

`Next.js` `TypeScript` `React` `Tailwind CSS` `TanStack Query` `Zod` `MongoDB Atlas` `RESTHeart` `Vercel` `Vitest` `GitHub Actions`

### 🔌 WhatsApp Dispatcher — Sistema de Disparo de Mensagens `Estudo de Caso`

Um **estudo de caso de arquitetura** (implementação parcial) sobre como projetar um sistema confiável de disparo de mensagens no WhatsApp para campanhas e fluxos automatizados.

O estudo cobre **Domain-Driven Design, Clean Architecture, Arquitetura Hexagonal, processamento assíncrono com filas e workers (BullMQ + Redis), idempotência, retentativas com backoff, tolerância a falhas, locks distribuídos e confiabilidade de sistemas**, com foco no raciocínio por trás das decisões arquiteturais e nos seus trade-offs.

[→ Ler o Estudo de Caso](https://mariabdev.netlify.app/cases/whatsapp-dispatcher)

### 🔗 [ShortURL](https://github.com/maria-brito15/shorturl-express) — Encurtador de URLs com Analytics de Cliques

Um encurtador de URLs pronto para produção, com **camada de cache em Redis** para redirecionamentos em submilissegundos e contagem atômica de cliques.

**Destaques:**
- Cache em Redis com TTL de 10 minutos — em caso de cache miss, busca no MongoDB e repopula automaticamente
- Contador atômico de cliques incrementado de forma assíncrona a cada redirecionamento
- Middleware de validação com Zod rejeita URLs malformadas antes de chegar ao controller
- API REST + frontend estático servidos pelo mesmo servidor Express
- Docker Compose completo: um comando sobe a API, o MongoDB e o Redis

`Node.js 20` `TypeScript 5` `Express` `MongoDB` `Redis` `Zod` `Docker` `GitHub Actions`
